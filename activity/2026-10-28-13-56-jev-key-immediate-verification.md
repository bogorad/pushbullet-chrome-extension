# Verify Jev API key immediately on paste in options (1.5.29)

- Bead: pushbullet-chrome-extension-hwd (open, P2, task). Not closed.
- Trigger: `paste` (0 ms), `change` (0 ms), and `input` (500 ms debounce) on `#jev-api-key` in `src/options/index.ts`; value is re-read when the timer fires so a paste into an empty field verifies the pasted value.
- Verify: new `verifyJevApiKey()` in `src/app/api/jev.ts` does one `GET https://api.typesafe.ai/v1/models` with the candidate key only in the `Authorization` header, 8 s AbortController timeout, no retries. Results: `valid` (2xx), `invalid` (401/403), `timeout` (abort), `network-error` (throw/other HTTP). Key/header never logged (status only).
- Feedback: inline `#jev-api-key-status` text plus `#jev-key-dot` in `options.html`/`css/options.css`. States: neutral gray (no key / saved-not-yet-verified), pulsing amber (verifying), green (valid), red (invalid/failed). Dot carries matching `title`/`aria-label`; status text is `role=status`/`aria-live=polite`.
- Storage rule: key is written via `setJevApiKey()` (chrome.storage.local only, sync untouched) only after a `valid` result. Invalid/network/timeout leaves the previously stored key unchanged; the inline message says so. Empty value clears the stored key with no network call. `Save All Settings` now routes the Jev key through the same verified path and reports an error instead of success when verification fails.
- On load: a stored key is shown in the password field (browser-masked), dot starts neutral with "Saved Jev API key — verifying…", and one verification runs immediately in this session; green is shown only after that fresh verification succeeds.
- Tests (mock fetch only, fake key strings only, no real API call): new `tests/app/jev-verify.test.ts` (5 tests: 200/header, 401, network throw, abort timeout, empty no-fetch) and 5 new options tests in `tests/options/options.test.ts` (paste verifies once + stores + green dot; 401 red dot + not stored; network error red dot + not stored; typed input debounce + empty clears with no fetch; stored key verified on load + green dot). Failing-first: the new verify suite failed 5/5 with `verifyJevApiKey is not a function` before implementation.
- Checks (direnv/nix shell): `npm run test` 251 passed (36 files); `npm run typecheck` pass; `tsc -p tsconfig.test.json --noEmit` pass; `npm run lint` pass; `npm run build` pass, build-dirtied tracked `dist/` reverted.
